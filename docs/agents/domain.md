# Domain documentation

Read the root `CONTEXT.md` before exploring product behavior. Use its defined terms in specifications, tests, and issue titles.

Read relevant decisions in `docs/adr/` when that directory exists. The repository is treated as one domain context; no `CONTEXT-MAP.md` is needed. Missing optional domain documents do not block work.

Surface any conflict with an existing ADR explicitly. Add domain terms or ADRs only when a real decision has been made.
