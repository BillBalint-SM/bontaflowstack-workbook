# Findings and verification

A finding contains the affected task, location or URL, viewport/environment,
reproduction, expected result, actual result and the supporting screenshot,
log or source reference. Use one finding for one underlying defect.

Prioritize by impact: data/security loss; blocked primary task; degraded task;
cosmetic inconsistency. Explain the concrete consequence. Missing access or
service availability is a blocker, not a demonstrated product bug.

A report includes tested scope, untested scope, original findings, any requested
repairs, retest results and remaining work. Each repaired finding links its
original evidence to the actual repeated interaction or regression check.

Optional scoring must state its rubric and coverage. Exclude untested areas
and compare only matching categories and conditions.
